## 2. Source truth

The browser may submit only the source SC01 archive asset ID.

A valid source must be proven by both:

1. latest durable P3 `ARCHIVE_SNAPSHOT` in `archives.jsonl`, and

- `workflow_code=SC01`;

- standardized SC01 Cutout filename;
- Site/SKU identity match;
- current F bytes still match persisted SHA256 and byte size;
- path remains inside Site Profile formal `asset_root`.

No browser-supplied D/F path, output path, destination path, filename, SHA or size is trusted.

## 3. Renderer

Renderer ID: `sd01-flat-gallery-surface-rgb-v1`.

Input support remains the same fail-closed 8-bit non-interlaced RGBA PNG contract used by SW01.

Background RGB for exact `#171B20`:

- R = 23
- G = 27
- B = 32

Each source pixel is alpha-composited over that exact background. Output must be deterministic opaque RGB PNG with identical width/height.

## 4. D staging

Directory:

`<staging_root>/visual-console/<SKU>/dark/`

`{SKU}__dark__master__wf-SD01__vNNN.png`

Rules:

- generated bytes are reread and compared with renderer output before QA_PENDING is persisted.

## 5. Durable journal

Use a dedicated append-only journal under existing `control_root`:

`dark-derivatives.jsonl`

States:

`GENERATING -> QA_PENDING -> QA_PASS | QA_FAIL`

Failure state:

`FAILED_GENERATION`

Persist source archive identity, output identity, dimensions, renderer ID, version and QA note. Raw filesystem paths remain internal and are removed from public API responses.

On restart, a torn final JSONL line may be ignored; earlier corruption fails closed. A durable `GENERATING` snapshot must be reconstructed only if verified source + deterministic rerender + existing D bytes all agree exactly; otherwise mark `FAILED_GENERATION`.

## 6. QA

SD01 validation supports individual:

- PASS;
- FAIL;
- NOTE.

QA mutations require the persisted generated D file to still match its SHA256/size snapshot. An already archived Dark Master cannot be reclassified.

No bulk PASS is required for P4C validation.

## 7. Gate15 Dark archive

Only `SD01 QA_PASS` may archive.

Destination comes only from `Manifest.destinations.dark` and must remain under formal `asset_root`.

Safety order:

1. server-side derivative identity;
2. verify D source snapshot;
3. resolve/validate `destinations.dark`;
4. F create/no-overwrite;
5. verify F SHA256 + size;
6. atomically append exactly one matching Manifest Gate15 history row;
7. re-verify F;
8. delete D source last;
9. append `ARCHIVE_SNAPSHOT` to shared archive journal.

Retry after durable history is idempotent. Same-name/different-content or conflicting history fails closed.
