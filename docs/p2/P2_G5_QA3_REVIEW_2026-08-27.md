## Findings requiring S7 repair

### G5-P1-01 — Frozen SC01 model/class is not actually enforced

Severity: `P1 / BLOCKING_G5`

The machine-readable Workflow Registry freezes `model = RMBG-2.0`, but `validateSc01Workflow()` identifies the RMBG candidate only by the numeric/boolean parameter signature. It does not require the expected RMBG class nor `inputs.model === "RMBG-2.0"`.

Impact:

- the currently registered real workflow is known from Human Owner evidence to use the correct RMBG-2.0 graph, so there is no evidence that existing `v001-v004` outputs are contaminated;
- however, after a control-state reset/new site/re-registration, a graph with the same numeric fields but a different model—or a non-RMBG node carrying the same field names—could satisfy the guardrail and be marked REGISTERED;
- this violates the frozen-runtime intent and weakens the production binding boundary.

Required bounded repair:

- explicitly validate the supported RMBG `class_type` representation(s) used by the production API JSON;
- require `inputs.model === "RMBG-2.0"`;
- add negative regression tests for model drift and unrelated-class signature mimicry;
- preserve the already accepted `background` vs `background_color` behavior.

### G5-P1-02 — Restart recovery can strand a persisted `CAPTURED` job

Severity: `P1 / BLOCKING_G5`

The approved state machine contains `... GENERATED → CAPTURED → QA_PENDING ...`, and the Packet requires latest-state reconstruction after restart. The runtime persists `CAPTURED` before persisting `QA_PENDING`, but startup requeues only `READY / QUEUED / RUNNING / GENERATED`.

Impact:

- a process interruption in the small but real interval after the staging asset and `CAPTURED` snapshot are durable, but before the `QA_PENDING` snapshot is appended, leaves the job reconstructed as `CAPTURED`;
- `CAPTURED` is not requeued and is not an actionable QA state, so the generated asset can become stranded until manual intervention;
- no source/output data loss is implied, but the deterministic restart contract is incomplete.

Required bounded repair:

- on journal reconstruction, normalize a valid persisted `CAPTURED` job with generated-asset metadata to `QA_PENDING` and persist the recovered snapshot;
- fail closed with an explicit capture failure if the `CAPTURED` snapshot lacks required generated-asset metadata;
- add a focused restart regression test covering the exact `CAPTURED` crash window;
- do not rerun ComfyUI or create a duplicate `vNNN` during this recovery.
