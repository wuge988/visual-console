## Residual findings

No P0/P1 browser/UI or data-safety blocker was identified for the current single-operator Private-LAN P1 scope.

### G5-RISK-01 — QR upload token is embedded in URL — `P2 / ACCEPTABLE_IN_CURRENT_SCOPE`

The mobile token appears in the QR URL. This is acceptable only while the product remains Private-LAN, single-operator and non-public. Any cloud tunnel, public exposure, shared-network rollout or externally reachable mobile entry requires a new security design before exposure.

### G5-RISK-02 — LAN health metadata is readable — `P2 / ACCEPTABLE_IN_CURRENT_SCOPE`

`/api/health` exposes LAN candidate metadata to LAN callers. This does not expose user files and is acceptable for current local diagnostics, but should be reduced before broader network exposure.

### G5-RISK-03 — Trash audit append follows file movement — `P2 / ACCEPTABLE_WITH_DOCUMENTED_SEMANTICS`

The asset is safely moved and verified before `trash-index.jsonl` append. If audit append fails, the API may report failure even though the file already reached Trash. This is a consistency/observability issue, not a user-data-loss path. It should be improved before Trash becomes a multi-user or automated retention system.

### G5-RISK-04 — Session/chunk state is in-memory — `P2 / INTENTIONAL_P1_LIMIT`

Service restart invalidates Sessions and active chunk state. For P1 this is acceptable because the operator can regenerate a QR and retry; restart-resume remains explicitly out of scope.

### G5-RISK-05 — capture-lane policy for multiple simultaneous operators is undefined — `P2 / DEFERRED`

Current evidence is for one operator / one workstation / one iPhone capture flow. Multi-user or multi-device concurrent capture must not be inferred as supported.

### G5-RISK-06 — no-confirmation Trash action — `P2 / OWNER-ACCEPTED_PRODUCT_DECISION`

The Owner explicitly requested removal of the confirmation dialog for speed. Risk is bounded because the action moves to Site Trash instead of permanently deleting. The compact `×` is desktop-only and the Trash audit record preserves provenance. A future Restore UI may improve recoverability but is not required for P1.
